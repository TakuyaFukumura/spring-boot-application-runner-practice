# コードリーディング補助資料

## 処理の流れ

```text
main
  -> SpringApplication.run
  -> StartupOrderRunner (@Order(1))
  -> OrderApplicationRunner (@Order(2))
       -> CliCommandParser
       -> OrderCommandService
       -> OrderApplicationService
       -> OrderRepository (domain abstraction)
       -> InMemoryOrderRepository (infrastructure)
       -> OrderOutput (stdout)
```

`ApplicationRunner` は `ApplicationArguments` を受け取り、Parser・Application Service・出力へ
委譲するだけです。注文生成、制約判定、Repository 操作は Runner にありません。

## レイヤーの読み方

1. `presentation`: Spring Boot の起動と CLI アダプター。通常引数の `register`/`list` を
   Application DTO に変換する。
2. `application`: ユースケースの手順を調整し、Domain に依存する。DTO は外部へ Domain
   オブジェクトを漏らさない。
3. `domain`: Value Object と Order 集約、Repository 抽象。Spring/CLI 型を参照しない。
4. `infrastructure`: Domain の Repository 抽象をインメモリで実装する。

`OrderId`、`ProductName`、`Quantity` が値の不変条件を守り、`Order` は ID と 1 件の
`OrderLine` を集約します。重複登録は `DuplicateOrderException` で明示されます。

## 終了コードと出力

正常終了は `SpringApplication.exit` により 0、不正入力・ドメイン違反・ユースケース失敗は
エントリーポイントが例外をログへ記録して 1 を返します。業務結果は標準出力とし、ログと
混在させません。`docs/要件定義書.md` の受け入れ基準は本実装で満たしています。

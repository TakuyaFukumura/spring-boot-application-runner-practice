## 2. 背景・目的

Spring Boot アプリケーションの起動直後に一度だけ実行される処理を、`ApplicationRunner`
インタフェースを使って実装・実行する方法を学ぶ。

単にコードを動かすだけでなく、以下を確認できる教材とする。

- `ApplicationRunner` の実装方法
- `run(ApplicationArguments args)` の引数の扱い
- `--key=value`、`--flag` などのコマンドライン引数の取得方法
- Spring Bean として登録する方法
- 複数の Runner の実行順序を制御する方法
- 起動処理の成功・失敗とアプリケーション終了コードの扱い
- 実行ログから、いつ何が実行されたかを確認する方法

## 3. 対象範囲

### 3.1 対象

- ローカル環境で実行できる Spring Boot のコンソールアプリケーション
- `ApplicationRunner` を中心とした最小構成のサンプルコード
- 学習者がコマンドライン引数を変更して挙動を確認できること
- ソースコード内の日本語解説コメント
- README によるセットアップ、実行方法、確認ポイントの説明
- 自動テストによる主要な挙動の確認

### 3.2 対象外

- Web API、画面、データベース、外部メッセージング基盤
- 本番運用を想定したジョブスケジューラや分散実行
- Spring Batch の詳細な使い方
- 複雑な業務ロジックの実装
- CI/CD の構築（必要性は別途検討する）

- Spring Boot 4.1.1 は、実装開始時点で公式リリースおよび互換性を確認する。

- 学習環境で依存関係の安定性を優先する場合は、Java 21 と Spring Boot 3.5.x を代替案とする。
- バージョン番号は「学習者の環境で実際に再現できること」を優先して最終確定する。

## 5. 機能要件

### FR-001: アプリケーションを起動できる

- ビルドツールの標準コマンドでアプリケーションを起動できる。
- 起動時に Spring Boot のアプリケーションコンテキストが初期化される。
- Web サーバーは起動せず、コンソールアプリケーションとして動作する。

### FR-002: `ApplicationRunner` を実装する

- `ApplicationRunner` を実装したクラスを少なくとも 1 つ用意する。
- `run(ApplicationArguments args)` がアプリケーション起動後に呼び出されることを確認できる。
- 1回のApplicationContext起動につき、Runnerの処理が1回だけ実行される。
- 実行されたことが分かるログを出力する。
- 処理内容は学習目的に適した簡単な例にする。

### FR-003: コマンドライン引数を扱う

- `--name=Taro` のようなオプション引数を取得できる。
- `--verbose` のようなフラグ引数の有無を判定できる。
- 引数が指定されなかった場合のデフォルト値を定義する。
- `--name`が空の場合はエラーとして起動を失敗させる。
- `ApplicationArguments` の代表的な API（例: `containsOption`、`getOptionValues`、
  `getNonOptionArgs`）をコメント付きで示す。

### FR-004: 実行順序を学べる

- 必要に応じて複数の Runner を用意する。
- `@Order` または `Ordered` を使って実行順序を明示できる例を示す。
- 順序制御が不要な場合との差分をコメントまたは README で説明する。

### FR-005: 終了結果を確認できる

- 正常終了時に、処理が完了したことをログで確認できる。
- 異常系を扱う場合は、例外を握りつぶさず、原因が分かる形で失敗させる。
- 引数エラー時は終了コード1で終了する。

### FR-006: 解説コメントを付ける

- Spring Boot のエントリーポイントに、`@SpringBootApplication` の役割を説明する。
- Runner の実装に、Bean 登録、起動タイミング、引数取得を説明する。
- コメントはコードの逐語訳ではなく、「なぜこの書き方をするか」を中心にする。
- 実行方法と期待されるログ例を README に記載する。

## 7. 想定する実行例

最終的なコマンドはビルドツール決定後に確定する。以下は挙動のイメージである。

```text
アプリケーションを起動する
  ↓
Spring コンテキストを初期化する
  ↓
ApplicationRunner.run(...) が呼び出される
  ↓
--name、--verbose などの引数を読み取る
  ↓
処理結果をログに出力する
  ↓
アプリケーションを正常終了する
```

例:

```text
.\mvnw.cmd spring-boot:run -Dspring-boot.run.arguments="--name=Taro --verbose input.txt"
```

期待する確認内容:

- `name` に `Taro` が設定されている。
- `verbose` が有効として判定されている。
- Runner が Spring Boot 起動完了後に実行されている。
- 実行完了後、プロセスが終了する（Web アプリケーションとして待機しない）。
